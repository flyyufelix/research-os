Literature Scout

Search from your research gaps

Use the current manifesto to find recent work, missing evidence, competing explanations, and follow-ups to core sources. Review every candidate before it becomes part of the Research OS.

How Literature Scout works

Literature Scout produces a ranked discovery report for human review. It does not automatically index papers or change manifesto.md.

Each run reads your manifesto, existing library, search scope, and previously seen candidates. It then searches several focused query lanes and records what worked, what failed, and what material it examined.

  1. Build queries from the manifesto

    Search the main direction, evidence gaps, competing hypotheses, and related work around core sources.

  2. Use complementary channels

    Combine broad web discovery with structured scholarly metadata and citation links when those tools are available.

  3. Deduplicate and rank

    Remove items already indexed or previously reported, then rank candidates by explicit relevance and source quality.

  4. Save a reviewable report

    Record discovery path, verification source, material examined, caveats, and the candidate’s connection to the manifesto.

1. Configure the search

Open scout/scope.md after your first manifesto exists. Replace the placeholders with settings for your project.

## Research focus

- Domains: [your disciplines or research areas]
- Search vocabulary: [terms and synonyms not already in manifesto.md]
- Nearby topics to include: [optional]
- Topics to exclude: [optional]

## Run limits

- Lookback period: 30 days
- Maximum findings: 5
- Languages: English
- Timezone: Asia/Hong_Kong

Keep the default retrieval policy unless your field needs different databases. A maximum of five findings is a useful starting point because it forces the scout to rank rather than dump results.

2. Run one manual test

Run Literature Scout once using scout/scope.md. Save the dated report, but do not index candidates or change manifesto.md.

Open the new file under scout/reports/. A useful report should explain its searches, retrieval tools, coverage limits, duplicates, and exclusion decisions—not only list titles.

3. Review candidates

  • The candidate has a direct connection to a manifesto question, gap, uncertainty, or competing hypothesis.
  • The report identifies whether the assessment used metadata, an abstract, a full post, or fuller text.
  • The title, authors, date, DOI or stable identifier, and canonical URL were verified where possible.
  • Blog posts and news are labeled as leads rather than treated as primary evidence.
  • Unavailable databases or failed retrieval methods are visible in the coverage section.

For a useful candidate, ask the update workflow to index it:

Index candidate 2 from the latest scout report and update my Research OS.

See a completed scout report with ranked findings, relevance explanations, caveats, and coverage notes.

Optional: connect scholarly MCP servers

MCP is a standard way for an AI agent to call external tools and data services. Scholarly MCP servers can add structured metadata, stable identifiers, citation relationships, and open-access discovery to the broad web search.

Start without MCP

Run the basic scout once using ordinary web search. Add an MCP only after the baseline workflow works and you understand what access the server requests.

Recommended first connection: OpenAlex

OpenAlex provides an official remote MCP server. It supports structured literature queries, citation and reference traversal, related works, author and institution discovery, and identifier checks.

https://mcp.openalex.org/mcp

Ask your agent to guide the setup

The simplest route is to give your agent the MCP URL and let it explain the controls available in its current version. Paste this into ChatGPT Work, Tencent WorkBuddy, QwenWork, Doubao Work, or another agent you prefer:

Help me connect the official OpenAlex MCP server to this agent:
https://mcp.openalex.org/mcp

Walk me through the setup step by step. Explain each permission before I approve it, then test the connection with one narrow scholarly query. If this version cannot connect to custom MCP servers, tell me clearly and use ordinary web search instead.
  1. Paste the prompt into the agent you are using for Research OS.
  2. Follow its current on-screen instructions and review every requested permission.
  3. After the test succeeds, run Literature Scout again and compare the coverage with your baseline report.

Interface names change between products and versions, so the agent’s live guidance is more reliable than a fixed menu path. You can also consult the official OpenAlex MCP guide.

Advanced option: paper-search-mcp

paper-search-mcp is a third-party, multi-source server for searching scholarly indexes and finding lawful open-access copies. Its installation details and supported providers can change, so follow the maintained project instructions rather than copying an old configuration.

Open paper-search-mcp documentation

If you want to try it, ask your agent to review the maintained instructions and guide you interactively:

Help me evaluate and set up paper-search-mcp for this Research OS project:
https://github.com/openags/paper-search-mcp

Review the current installation instructions, explain what will be installed and what access it requests, then guide me step by step. Do not store credentials in the repository. If setup is not available in this agent, continue with ordinary web search.

Keep restricted sources off

Prefer publishers, repositories, and open-access services. Research OS does not recommend or enable Sci-Hub. Do not bypass access restrictions.

Connection safety

  • Review the server’s publisher, source code, permissions, and data policy.
  • Prefer remote OAuth or a narrowly scoped project configuration.
  • Never store API keys, tokens, webhook URLs, or personal email addresses in the public repository.
  • Limit local file access to the Research OS directory.
  • Verify shortlisted findings against a publisher, DOI record, or primary repository.

Describe coverage honestly

More tools improve discovery, but they do not make a search exhaustive. A scout report must identify failed or missing retrieval methods and describe the resulting coverage as limited or degraded. MCP output still requires source verification and researcher judgment.

Schedule only after the manual run

Once the scope produces useful results, ask your agent to schedule the same bounded workflow. A weekly run is a reasonable starting point.

Create a local scheduled task that runs Literature Scout every Monday at 8:00 AM Hong Kong time. Follow scout/scope.md, save the report, and do not index candidates or change manifesto.md.

A local schedule needs the computer, project, and agent application to be available. Cloud schedules need authorized access to lasting project files.
