Common problems

Get the workflow moving again

Most setup problems come from opening the wrong folder, missing file permissions, or expecting an unavailable search connection.

Project and folder problems

The agent cannot find AGENTS.md or the skills

Open the repository root—the folder that directly contains AGENTS.md, skills/, scout/, and staging-material/. If you downloaded a ZIP, check that you did not select an outer folder containing another nested research-os-main folder.

The agent writes files somewhere else

Create a new local task and select the Research OS directory before sending the prompt. Confirm that the task’s displayed working directory matches the repository root.

The ZIP contains a folder named research-os-main

That is normal. You may rename it to research-os. Open this extracted folder directly in the agent.

Permission problems

The agent can read files but cannot create manifesto.md

Grant read and write access to the Research OS directory. You do not need to grant access to your home folder, entire drive, or unrelated projects.

The agent repeatedly asks for approval

Approve ordinary file creation inside the selected project as needed. Keep review checkpoints for actions outside the folder, external messages, credentials, deletions, and other consequential operations.

The workflow does not start automatically

Use an explicit instruction:

Read AGENTS.md and skills/bootstrap-research-os/SKILL.md completely, then build my Research OS using everything in staging-material.

Manifesto and source problems

The agent asks me to write manifesto.md myself

You only need to write the starting material in staging-material/ideas.md. Ask the agent to follow the bootstrap workflow; it should preserve your starting ideas and draft the manifesto for review.

The manifesto sounds too certain

Do not approve it. Ask the agent to distinguish source-supported claims, your own statements, agent interpretation, and uncertainty. Preserve competing hypotheses and state what evidence could change the current view.

A long book was not read from cover to cover

This is expected. Research OS maps long works, then closely reads selected sections that can affect the research direction. Check the source note for exact chapters or pages examined.

A PDF cannot be accessed or parsed

Keep the source in staging, record the failure, and continue with accessible material. Try a lawful open-access copy or a text-enabled PDF. Do not claim the inaccessible source was reviewed.

Literature-search problems

Web search works but an MCP server is unavailable

Continue the scout with web search and any other available scholarly connection. The report should name the missing method and describe structured or citation-graph coverage as limited.

OpenAlex asks me to sign in

The official OpenAlex remote MCP uses account authorization. Confirm that you are on mcp.openalex.org, review the access request, and do not paste tokens into the repository.

The report returns too many weak results

Narrow scout/scope.md: add field-specific terms, exclusions, important populations, locations, methods, or core sources. Keep the maximum findings small while tuning.

The same paper appears again

Check scout/_seen.md and library/_index.md. Literature Scout should deduplicate by DOI or another stable identifier before using normalized title and year.

Can I call the search comprehensive?

Only make a strong coverage claim when every required method was attempted successfully and the scope justifies it. Otherwise describe what was searched and state the limitations directly.

Still stuck?

Ask your agent to diagnose the workspace without changing files:

Inspect this Research OS project and explain why the requested workflow did not run. Do not modify any files. Check the working directory, permissions, required inputs, and available research tools.

You can also open a GitHub issue with the agent name, operating system, prompt used, and a description of the result. Remove credentials and private research material first.
